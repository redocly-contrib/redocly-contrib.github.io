Features

Read the story. Judge the code that matters.

Only the important code, as a story

Every walkthrough comes as an exec summary, to decide in a minute, and an engineer walkthrough, to review the code that matters step by step. Each step says what changes, before and after, in a sentence. Everything else is folded away.

Only the lines that matter

Big hunks fold to the few lines that carry the change; open the rest when you need it.

  • Your agent names the load-bearing lines of every big hunk.
  • The lines around them fold away, each run into one bar: “⋯ 21 lines around the change”.
  • Show opens a fold, its lines dimmed; Focus in the top bar, or z, shows every line again.

Risk that knows your repository

Run rev scan in a clone: it reads the last 12 months of your default branch and its merged pull requests, and your agent writes review guidance for each area. It all goes in .rev/insights.json. Commit it through a normal pull request and the whole team shares it.

  • For each file: its reverts and hotfixes, the files it usually changes with, and markers such as migrations.
  • Risk scores and walkthroughs read it from the default branch; a reason from history names the file and its pull request.
  • Size alone never makes a pull request risky; it only adds weight to other reasons.

Comments where they belong

GitHub's review threads sit right under the line they are about, in Unified and in Split, and so do your Notes for AI and the comment you are writing. Reply, resolve and react as on GitHub, then submit your review to GitHub.

  • Any of GitHub's eight reactions; yours show pressed.
  • Focus never folds away a line with a comment under it.
  • h hides every comment, and shows them again.

Review the files you own

In the changed files and in Code mode's file tree, Mine leaves the files CODEOWNERS gives you or your teams, and Hide tests and generated takes out tests, snapshots, lockfiles and generated files. The tree says how many they hide, and Show all brings them back.

  • For a pull request, CODEOWNERS is read at its base branch, as GitHub reads it.
  • Your teams come through gh; without them, Mine counts the rules that name you.
  • The filters stay on for your next review.

A simple code view, built in

When the story is not enough, open the whole file or Cmd-click a name to go to its definition, without leaving the review.

Checkouts recycle themselves

Each pull request rev checks out gets a worktree of its own. rev removes those of merged and closed pull requests, of pull requests not opened for a week, and all but the 5 opened last, never one in use. On Home, Archive in a card's menu removes one, and Free up space every one not in use. Walkthroughs, notes and progress stay.

Review your own changes before you push

Open a folder to walk through your own work: its uncommitted changes, the last commit, everything since main, or one commit, with the changed files as a tree. Leave notes for AI on the lines that need another pass, then Copy for AI and paste them into your agent.

Sharing

Share with your team. Sign up for nothing.

A walkthrough is stored as a git ref in the same GitHub repository as the code, pushed with the git and gh login you already have, and the pull request's description gets an “Open in rev” link. No rev account, no server, no SaaS, no tokens: anyone with access to the repository opens it in rev.

Share when your agent is done, or later: Share sits on a walkthrough still on your Mac, in its row of the pull request's list, in the review's top bar and in the command palette.

Sharing uses what you have

  • Your GitHub repository, and who can read it
  • Your git credentials, for the push
  • Your gh login, for the link in the description

And never needs

  • A rev account
  • A rev server, or any SaaS
  • API tokens or secrets to set up
  • An app installed on GitHub

The “Open in rev” link goes through a static page that holds no data: the pull request travels in the link's #fragment, which browsers never send. rev refuses to share a walkthrough that looks like it holds a secret, and the walkthroughs of a folder's own changes never leave your Mac.

How it works

From pull request to review in three steps

  1. 1Open a pull request

    From its “Open in rev” link, by pasting its link, or with rev open.

  2. 2Generate with your agent

    Your agent reads the change and writes both walkthroughs. Share them, then or later, and rev pushes a git ref and links it from the pull request: nobody else has to wait.

  3. 3Read the story and review

    Step through the story, comment on the lines, and submit your review to GitHub.

Install

Up and running in a minute

  1. Download the latest release

    The disk image for Macs with Apple Silicon. Sign in to GitHub with an account that has access to redocly-contrib/rev first, as the repository is private.

  2. Drag rev to Applications

    Open the disk image and drag rev into the Applications folder.

  3. Open it like any app

    rev is signed by Redocly and notarized by Apple, so it opens like any other app you download. New versions come to you: when one is out, a banner offers Update and restart.

  4. Add the rev command

    The command line tool comes with the app: choose rev › Install Command Line Tool.
